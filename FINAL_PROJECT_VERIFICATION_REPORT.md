## 3. SEMANTIC CORRECTION AUDIT (THE 4 ISSUES)

### Issue 1: Market Insight Evidence Score vs Overall Signal Percentage
- **Forensic Audit**: Audited `src/models/trading_decision.py` and `src/services/signal_aggregator.py`. Proved that no separate backend field exists for a distinct 'Market Insight Evidence Score'. The `OverallTradingSignal` model contains `signal`, `percentage`, `strength`, `confidence`, `overall_evidence_score`, `component_weights`, and `contributors`.
- **Resolution (Case B)**: Under Case B, Market Insight does NOT substitute `overall_signal.percentage` as its hero metric, preventing semantic confusion with the Overall platform decision. The Market Insight Hero displays `Metric: --`, titled `MARKET INSIGHT · FULL-SYSTEM EVIDENCE SYNTHESIS`, with status badge `4-COMPONENT CONVICTION LEDGER`, accompanied by the full 4-factor contributor breakdown (Technical 35%, Historical 35%, ML 15%, Strategy 15%). The authoritative `Overall Signal Strength: XX%` remains strictly on the `OVERALL` page.

### Issue 2: History Market Label
- **Forensic Audit**: Audited `src/models/trading_decision.py` and `src/services/historical_evidence_service.py`. The actual quantitative field generated by historical matching is `historical_win_rate` (0.0% to 100.0%).
- **Resolution**: In `frontend/src/app/page.tsx` line 5985, the supporting metric pill is labeled strictly as `Historical Win Rate: XX%`. The confusing term `Historical Support` has been completely eliminated.

### Issue 3: Removal of Unverified N >= 10 Rule in Frontend
- **Forensic Audit**: Audited `src/services/historical_evidence_service.py`. The backend itself explicitly implements statistical thresholding:
  ```python
  if sample_size < 10:
      win_rate = None
  ```
  The frontend had previously invented a client-side gate `if (sampleSize < 10) return null;`, which was unverified and duplicated backend business logic.
- **Resolution**: In `frontend/src/lib/format.ts`, `resolveHistoryMarketPercentage` and `resolveMLShadowAccuracy` were updated to respect backend data lineage directly. If the backend provides a valid, finite number, it is formatted and rounded. If the backend emits `null`/`None` (due to N < 10), the frontend displays truthful `--`.

### Issue 4: ML Prediction Target & Probability Semantics
- **Forensic Audit**: Traced `src/research/ml/dataset_builder.py` (lines 73-75) and `src/research/ml_shadow/shadow_service.py` (line 169):
  ```python
  # Binary target: 1 = WIN (TP1 hit before SL), 0 = LOSS
  y = (df['outcome'] == 'WIN').astype(int)
  prob = model.predict_proba(X_vec)[0, 1]
  ```
  Class 1 probability strictly represents **Trade Win Probability / Success Probability** for the candidate setup (whether BUY or SELL). It is NEVER 'BUY Probability'.
- **Resolution**: In `frontend/src/app/page.tsx`, labeled as `Model Win Prob: XX%` (line 6262 and line 3947) and `Trade Win Probability` (line 4934), strictly distinct from post-T0 closed-candle `Validated Accuracy: XX% · N=YY`.
