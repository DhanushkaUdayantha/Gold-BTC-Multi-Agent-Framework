## 1. Executive Summary & Non-Negotiable Safety Invariants

This implementation introduces an additive, zero-regression, dual-asset shadow-mode validation layer for **BTC/USD** and **XAU/USD**. The system is strictly an **advisory and research analytics platform**. Under no flag state or configuration can the system execute live trades, place broker orders, or connect to broker execution endpoints.

### Hard-Enforced Invariants
1. **Zero Real Broker Connections**: Static AST and runtime inspection verifies zero imports of `ccxt`, `binance`, `alpaca`, `ibkr`, `oanda`, or any broker execution client, and zero live order calls across the codebase.
2. **Strict Advisory Status**: Signals generated by the platform are purely advisory and informational.
3. **Dual-Asset Independence**: BTC shadow operations and XAU shadow operations are strictly segregated. BTC events cannot mutate XAU records, and XAU events cannot mutate BTC records.
4. **Hard-Locked XAU Production Gating**: `PRODUCTION_GATING_XAU == False` is permanently enforced on every read and write. XAU remains strictly in shadow paper validation pending its $N \ge 50$ holdout milestone.
5. **Zero Automation of Retraining or Optimization**: `AUTOMATIC_RETRAINING == False` and `AUTOMATIC_THRESHOLD_OPTIMIZATION == False` are immutable system properties that raise exceptions if any code path attempts to enable them.
6. **Zero Regression on Disabled Default**: When gating is `DISABLED` (the default state), decision logic and outputs are byte-identical and snapshot-identical to pre-change baseline behavior.

## 4. Isolated Data Architecture

### Separation of Manual Demo & Shadow Store
- **User Demo Ledger**: `paper_trading.json` (managed by `PaperTradingService`). Stores simulated manual clicks from the web dashboard. `POST /trade/reset` wipes `paper_trading.json` and resets balance to $\$10,000$.
- **Research Shadow Ledger**: `data/shadow_trades.db` (managed by `ShadowTradingStore`). Stores deterministic shadow simulation trades.
- **Cross-Store Isolation**: `POST /trade/reset` has zero access to `data/shadow_trades.db`. Calling account reset leaves shadow histories completely untouched.
- **Cross-Asset Isolation**: Table rows are segregated by `asset="BTC/USD"` and `asset="XAU/USD"`. Operations on one asset cannot read, modify, or delete records belonging to the other.

## 5. Security & Authentication Architecture

### Minimal Timing-Attack Safe Admin Auth
- **Header**: `X-Admin-Token`
- **Verification**: Checked against `ADMIN_AUTH_TOKEN` environment variable via `secrets.compare_digest`.
- **Credential Protection**: The token is never logged, never hardcoded, and never exposed in responses.
- **Fail-Closed**: If `ADMIN_AUTH_TOKEN` is unset in the environment, the endpoint returns `503 Service Unavailable`.
- **Endpoints**:
  - `POST /api/v1/admin/gating/btc`: Enables BTC gating (Requires valid token, confirmation token `CONFIRM_MANUAL_BTC_GATING`, rationale, and comparison gate state `PASS`).
  - `POST /api/v1/admin/gating/btc/disable`: Symmetric kill switch (Requires valid token only; immediately reverts gating to `DISABLED`).
  - `POST /api/v1/admin/gating/xau`: Rejected (XAU gating is hard-locked `DISABLED`).
  - `POST /api/v1/admin/gating/xau/disable`: Confirms XAU is disabled.
  - `GET /api/v1/admin/gating/status`: Read-only gating status and invariant check.
- **Audit Trail**: Every gating state change appends an immutable JSON record to `data/audit/gating_audit.log` containing timestamp, actor, previous state, new state, validation state, and rationale.
